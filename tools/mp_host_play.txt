# The multiplayer host as a scripted player (tools/mpcheck.py
# tools/mp_host_play.txt tools/mp_client_play.txt 3000): hosts a LAN game,
# founds a company, builds a station in Washington DC, lays track from it,
# builds a second station on that track, then buys a train and routes it
# between the two stations. The client's weekly state checks must match the
# host's all along.
#
# Map positions are map cells (the harness "C" lines of "cities" give a
# city's cell: Washington DC is 509.9 233.6); "look" / "zoom" move the view
# with the game's own camera calls, "cell" / "cellclick" / "celldrag" find
# the cell on screen with the camera's ground pick.
#
# Things the game needs (found by trying, see the screenshots of "shot"):
# - In this scenario every new track or station must connect to the
#   company's track, so the first station comes first and the second one
#   goes onto the track laid from it.
# - One track drag lays at most about 6 cells; in multiplayer the pieces
#   arrive over the next frames and the tool refuses a new drag meanwhile.
# - The station tool is closed right after each click: its preview marks
#   the cells around the cursor on this PC only, and a weekly check taken
#   while it is open differs from the client's (cargo value, 0x46dac0) -
#   the original game's behaviour, not something to change here.
# - The train buyer is a dialog: Enter (which the harness presses in
#   dialogs) would press Buy before there is a route, so it is off there.
